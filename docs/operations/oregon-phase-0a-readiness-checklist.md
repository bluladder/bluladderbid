# BluLadder Oregon Phase 0A readiness checklist

Status: **planning and pure-test checkpoint only**. This checklist does not
authorize deployment, migration application, production mutation, provider
configuration, Lovable publication, Oregon activation, or customer traffic.

## Completed by Phase 0A

- [ ] Oregon launch contract is recorded as repository documentation only.
- [ ] Oregon remains inactive/provisioning.
- [ ] Planned Oregon hostnames are documented as future server-controlled
authority keys only.
- [ ] Pure tests prove inactive, missing, ambiguous, or conflicting authority
fails closed where existing contracts support those assertions.
- [ ] Pure tests prove Oregon cannot fall back to DFW pricing, contacts,
territory, CRM, or provider configuration.
- [ ] Pure tests prove unvalidated JobTread behavior remains manual-review or
unsupported rather than executing Jobber or another connector.
- [ ] Pure tests prove commercial/storefront Oregon service requests remain
manual-review.
- [ ] No real contact values, credentials, provider calls, customers, pricing
rates, migrations, generated types, or runtime changes are committed.

## Protected gates after Phase 0A

- [ ] Hosted tenant foundation migration is separately authorized, applied, and
verified.
- [ ] Hosted schema types are regenerated after verified hosted schema changes.
- [ ] Runtime organization adoption is completed for an explicitly named DFW
cohort before Oregon activation.
- [ ] Oregon organization status, hostnames, territory, services, pricing,
contacts, and connector configuration are implemented only in later authorized
phases.
- [ ] JobTread capabilities and account behavior are validated using official
provider/account evidence before any provider-backed Oregon workflow.
- [ ] Background jobs and cron paths are proven tenant-aware or safely
constrained before second-organization activation.
- [ ] Knowledge, attribution, recommendations, security-definer behavior,
customer records, quotes, bookings, CRM writes, and background jobs have
organization-scoped isolation tests.
- [ ] Unresolved uniqueness decisions are closed before Oregon becomes an active
organization.

## Unresolved business decisions

- [ ] One-way versus round-trip mileage basis for travel pricing.
- [ ] Final travel-charge mode governance: per-mile, flat fee, or territory-
specific combination.
- [ ] Territory day-of-week assignment governance, including remote route days.
- [ ] Authoritative address, county, and geocoder normalization rules.
- [ ] Oregon snow, ice, wildfire-smoke, and freezing-temperature policies.
- [ ] Exact JobTread capability matrix and credential-reference model.
- [ ] Where independently configurable local-manager and public-contact values
will be stored outside source code.

## Phase 0A prohibited actions

- [ ] No deployment.
- [ ] No migration authored or applied.
- [ ] No production or hosted data mutation.
- [ ] No Oregon activation or active territory/service configuration.
- [ ] No provider call or provider credential/configuration change.
- [ ] No Lovable publication or credit consumption.
- [ ] No PR #80 modification.
